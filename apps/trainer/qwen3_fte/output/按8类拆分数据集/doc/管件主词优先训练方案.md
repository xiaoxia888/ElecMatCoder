# 管件主词优先训练方案

## 1. 目标

这份方案不是为了解决某一条错例，而是为了解决一整类问题：

- 描述里主词很明确，但模型被低频修饰词带偏
- 同一套材质、标准、壁厚背景下，模型没有抓住真正决定类别的词
- 小模型更容易记住“整体长相”，而不是“谁才是主体”

训练目标要从“整句像什么”改成“先判断主体，再吸收修饰”。

## 2. 适用范围

本方案只针对 [管件.json](/Users/guoxi/Desktop/workspace/NJNCC/python_code/ElecMatCoder/apps/trainer/qwen3_fte/output/按8类拆分数据集/管件.json) 这一类管件训练集。

不把法兰单独混进来，避免 `CATEGORY=法兰` 和 `CATEGORY=管件` 互相污染。

## 3. 主体优先原则

### 3.1 谁是主词

主词是决定 `TYPE.BODY` 的核心词。

例如：

- `Cap / End Cap` 决定主体是 `管帽`
- `Elbow / 90EL / 45EL` 决定主体是 `弯头`
- `Tee / Equal Tee / Red Tee` 决定主体是 `三通 / 等径三通 / 异径三通`
- `Con Reducer / Ecc Reducer` 决定主体是 `同心异径管 / 偏心异径管`

### 3.2 谁是修饰词

以下内容都属于修饰信息，不能反过来主导 `BODY`：

- `SMLS / WELDED`
- `BW / SW / THD`
- `STD / SCH40 / SCH80`
- `A234 WPB / A420 WPL6 / A403 WP304L`
- `ASME B16.9 / SH/T3408`
- `Oval / Elliptical / LR / SR`

模型必须学到：

> 修饰词可以补充信息，但不应把主体从 `Cap` 带偏成 `异径管`。

## 4. 建议优先补强的主体族

### 4.1 管帽族

核心头词：

- `Cap`
- `CAP`
- `End Cap`
- `Pipe Cap`

低频变体：

- `Oval Cap`
- `Cap,Oval`
- `CAP OVAL`
- `Elliptical Cap`

### 4.2 弯头族

核心头词：

- `Elbow`
- `ELBOW`
- `90EL`
- `45EL`

修饰变体：

- `LR`
- `SR`
- `Long Radius`
- `Short Radius`
- `45`
- `90`

### 4.3 三通族

核心头词：

- `Tee`
- `Equal Tee`
- `Eq Tee`
- `Reducing Tee`
- `Red Tee`
- `Tee Red`

### 4.4 异径管族

核心头词：

- `Concentric Reducer`
- `Conc Reducer`
- `Con Reducer`
- `Eccentric Reducer`
- `Ecc Reducer`
- `Reducer Eccentric`

## 5. 数据构造原则

### 5.1 不补单句，补模板族

不要因为遇到 `Cap,Oval` 错了，就只补一条 `Cap,Oval`。

正确做法是补一整个表达族：

- `Cap,Oval`
- `Oval Cap`
- `CAP OVAL`
- `Elliptical Cap`
- `End Cap`

这样模型学到的是“这一组说法都围绕 Cap”，不是只记住一条句子。

### 5.2 做对抗组

背景尽量一致，只换主词。

例如：

- `Cap,Oval,SMLS,BW,A234 WPB,ASME B16.9 STD DN600`
- `Ecc Reducer,Oval,SMLS,BW,A234 WPB,ASME B16.9 STD DN600`
- `Con Reducer,Oval,SMLS,BW,A234 WPB,ASME B16.9 STD DN600`

这样模型会被强制学习：

> 决定类别的是 `Cap / Reducer`，不是后面的材质、标准、壁厚。

### 5.3 少样本类要主动补权重

当前 `管件.json` 里：

- `管帽` 约 241 条
- `弯头` 约 1574 条
- `异径三通` 约 1119 条
- `同心异径管` 约 693 条
- `偏心异径管` 约 682 条

这意味着 `管帽` 的话语权明显偏弱。  
不是它错了，而是它在模型里“不够响”。

## 7. 建议使用方式

### 方案 A：直接并入原训练集

适合先快速验证效果。

做法：

1. 把 `管件.json` 和 `管件_主词优先专项增强.json` 合并
2. 重新打乱
3. 重新划分 train / val

### 方案 B：只在 train 中加入增强样本

更稳。

做法：

1. 保持原始验证集不动
2. 只把增强样本并入训练集
3. 观察 `Cap/Oval`、`Reducer/Ecc`、`Equal Tee/Reducing Tee` 这些易混淆模式的提升
